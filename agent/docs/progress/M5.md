# M5 — Context Assembler

**Status: done.** 557 tests green in 31.5s · `tsc` clean · `npm run demo:m5`

The bar §33 sets:

> *Done when:* a 200-turn session stays in budget with no loss of coherence
> and assembly is under **100ms**.

`test/integration/context-perf.test.ts`: 200 turns, gather included, **0.8ms
measured against a 100ms bar**, in budget, newest turn verbatim, and the
model explicitly told what was dropped.

## Built

| Area | Where | What it is |
|---|---|---|
| The pure function | `cognition/context/assemble.ts` | fourteen blocks, budgeted, digested |
| Block data | `cognition/context/types.ts` | `SURVIVAL_ORDER`, `RENDER_ORDER`, `UNEVICTABLE`, `StateSnapshot` |
| Budgets | `cognition/context/policy.ts` | per-model shares, zod-validated, no magic numbers |
| Templates | `cognition/context/templates/` | six files, every block named and versioned |
| Tokens | `cognition/tokens.ts` | content-keyed memo + stable digest |
| Compaction | `cognition/compaction.ts` | structured extractive summaries, idempotent |
| Gathering | `orchestration/snapshot.ts` | the impure half; incremental session reads |
| Re-expansion | `tools/history-expand.ts` | the tool that makes compaction a view |
| Runner | `orchestration/runner.ts` | `context.assembled` per turn, overflow→compact→retry |

### The shape

```
gather (impure, L5)  ──►  assembleContext (pure, L4)  ──►  context.assembled
 log, memory, tools         14 blocks, budgets,              digest, blocks,
 one read per turn          eviction, templates              drops, policy
```

Everything that touches the world is on the left. What crosses the seam is a
frozen `StateSnapshot` — which is why twelve golden scenarios are a checked-in
object and a text file rather than a running system.

### Two orders, not one

`SURVIVAL_ORDER` is §21's table: who survives the squeeze. `RENDER_ORDER` is
what the model reads, top to bottom. They are different, and a test asserts
they stay different — kernel instructions survive everything and are read
first; the conversation is read last and squeezed early. One array cannot say
both, and collapsing them is the easiest bug in this file to write.

Blocks 1–4 (kernel, constitution, identity, constraints) are **unevictable**.
If they do not fit, assembly throws `ContextTooSmallError` rather than
shipping an agent with no taboos. An agent running without its constraints is
more dangerous than an agent that does not run.

### Honesty, rendered

- Every memory carries basis, confidence, source count and date. `[treat as
  a guess]` on anything inferred or below 0.5; `[DISPUTED]` where the
  evidence conflicts (invariant 5).
- A thin profile produces §24.4's paragraph, in words, in the context: *act
  like someone who has met them three times.* A rich profile does not. Both
  are golden-locked, so the day fabricated intimacy creeps back in, a file
  changes.
- Every drop is reported to the caller **and** to the model: *"23 earlier
  turns were dropped… do not reconstruct it."* A drop the caller can see but
  the model cannot is still a lie.
- `secret` memories are excluded unless policy allows; `quarantined` and
  `retired` never render at all, enforced at the template as well as at
  recall.

## Found while building

**Reading the golden files changed the budget algorithm.** The first
allocator walked survival order letting each block take whatever the blocks
below did not strictly need. The `near-overflow` golden showed what that
means at 2,400 tokens: retrieved memories took 1,003 tokens — 42% of the
window against a declared 16% share — and eleven live conversation turns were
evicted to pay for it. Neither number was predictable from the config.
Shares are now a real cap and the surplus is split proportionally; the same
scenario now keeps all 60 turns and drops 5 of 30 memories. Decision 026.
This is the second time a golden file has argued with a decision rather than
merely recording one — which is the case for keeping twelve of them.

**M2's signature had to go, and the note in the code was wrong, not the
spec.** M2's header promised this signature would survive to M5. §21
specifies `snapshot` + `policy`; three blocks fit through M2's hole and
fourteen do not. Said so out loud in decision 025 rather than bending §21 to
fit, and rewrote the M2 unit tests property-for-property against the new
shape — purity, ceiling, whole-item eviction, eviction reporting, fencing —
with nothing dropped.

**The fence had a delimiter-injection hole.** M2's close marker was a
constant, so untrusted content containing `<<<END_UNTRUSTED_CONTENT>>>`
closed its own fence and everything after it read as trusted text. Two
independent fixes: `<<<` and `>>>` inside the payload are visibly defanged,
and the close marker now carries the item's id. The substitution is visible,
not silent, because quietly rewriting untrusted text makes any summary of it
subtly wrong.

**M4's per-step log scans are gone.** Trust and history were each computed by
scanning the session, twice per step. The snapshotter reads the session
**once per turn** and derives both, then reads only *forward* from the last
sequence it saw. That is sound only because the log is append-only — the one
place where immutability makes caching trivial instead of dangerous. The run's
own trust floor is still read fresh every step and deliberately never cached:
a stale value there is a privilege escalation, not a slow page.

**L2 degradation was going to lie.** "Memory retrieval is unavailable" while
still serving recalled facts would have made the degradation note false.
L2 now returns no memories at all.

## Deferred

- **The working set is always empty.** Block 10 renders and is tested, but
  nothing populates it: artifacts live in M3's store and entities arrive at
  M6. Wiring it now would mean inventing a selection rule I would rewrite in
  a week.
- **Memory, identity, constraints, commitments and calibration all come from
  a `MemorySource` with no implementation.** The port is declared and the
  blocks render against it; M6 fills it in. The context says "you do not know
  this person yet", which is exactly true today.
- **`history.expand` is not registered with any registry.** It is built and
  tested, and it needs a `Compactor` and a run→session lookup that the
  built-in registration path does not yet thread through. One wiring job at
  M6, not a redesign.
- **Compaction is only triggered by overflow**, plus whatever a caller asks
  for. The scheduled "compact at 40 turns" pass belongs with M8's scheduler.
- **Per-model policies are a table in code, not a config file.** It is
  declaration rather than scattered magic numbers, which is what §21 asks
  for, but it is not yet user-editable.

## Unsure

- **The extractive summarizer is crude.** It finds decisions by matching
  phrases like "let's" and "I will". It will miss things. It cannot
  hallucinate — every string it emits was actually said (decision 024) — and
  I would rather ship obviously-partial structure than fluent invention, but
  a model summarizer is probably the right answer once there is a provider.
- **Characters ÷ 4 is still the token count** (decision 014). Fine for
  budgeting with a 25% output reserve; wrong enough to matter if someone
  starts billing against it.
- **The digest is FNV-1a, not sha256**, because the assembler is pure and
  synchronous and the `Hashing` port is async. A collision costs a confusing
  debugging session, not a security property — but it is a weaker guarantee
  than everything else in the log, and it is written down in `tokens.ts`.
- **Shares were chosen by argument, not by measurement.** Conversation 26%,
  memories 16%, tools 9%. The reasoning is in `policy.ts`; the numbers are
  unfalsified until there is real traffic.
- **Twelve golden files are a lot of surface.** If they start getting updated
  without being read, they will be worse than nothing. So far two of them
  have caught real design errors, which is the only evidence that matters.

## Decisions

024 compaction is an event (and the summarizer is extractive) ·
025 §21's signature wins over M2's promise ·
026 shares cap, surplus is proportional.
