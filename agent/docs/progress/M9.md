# M9 — Hardening & portability

**Status:** done · 838 agent tests green (45 new) · 140 web · 125 e2e
(6 new) · `tsc` clean · `npm run demo:m9` · `npm run perf` all budgets
met at 100k events / 50k facts

M9 is the only milestone whose subject is the whole system rather than a
layer of it, so it is organised around §34's thirteen-point definition of
done rather than around §33's feature list. Ten of the thirteen were
already asserted somewhere. Three were not, and they were the spine of
this milestone: **chaos (§34.1)**, **replay (§34.5)** and **a trace that
explains any sentence (§34.13)**.

All three now have tests. Along the way the work found four real defects
— one of them an invariant violation that had been true since M6 — and
those are the part of this note worth reading.

---

## Built

**Persona (§29, decision 036).** `src/cognition/persona/`, schema 012.
Six fields that decide how the agent *sounds*, kept sharply apart from
the constitution (what it may do) and the identity card (who the user
is). Rendered as sentences into block 1 and therefore unevictable — voice
that disappears under context pressure is an agent that gets colder as
the conversation gets longer. **User-editable only**: no tool, no
capability, `persona.updated` always written at USER trust.

**The trace, rendered (§30, §34.13).** `src/observability/trace.ts`.
`GET /runs/:id/trace` keeps its JSON and gains `?format=text`: the
assembled context with per-block token counts, every model call with
tokens/latency/cost, every tool call with duration and trust, every
recall with its component scores, approvals, effects, constitution
verdicts, degradation. Built from the log alone, so a run from two years
ago renders as well as one from two seconds ago. Test 18 asserts the
binding link — the model call's `contextDigest` equals the context's
digest, so the explanation is not a plausible reconstruction.

**Replay (§34.5).** `npm run replay -- <runId> [--trace]`. Rebuilds the
context that run would assemble *today* and diffs it block by block
against what was recorded. Zero diff means cognition has not drifted;
non-zero exits 1 and names the block, so it can gate a refactor in CI.
Opens the database read-only — a command that audits the log must not be
able to write to it. Two subtleties, both documented in code: it diffs
against the run's **first** assembly (later steps contain the run's own
output), and it reconstructs the conversation **as of** the run's start
(`GatherInput.asOfSeq`).

**Metrics (§30, decision 037).** `GET /metrics`, computed from the log.
No counters anywhere: the numbers survive a restart and a metric can
never disagree with a trace, because they are the same data read twice.
Each latency carries §32's budget and says whether it is met. Two
definitions stated out loud: denials are excluded from tool success rate
(a refused call is the system working), and memory hit rate is
`used ÷ offered` with both numbers reported.

**Export / import (§29, decision 038).** `src/portability/`. The export
is the event log plus the **sealed** vault — ciphertext and wrapped keys,
no plaintext, fuzzed for by test 32. Import refuses a non-empty database
(merging two hash chains is a different feature), verifies the chain
*before* projections exist, replays, rebuilds, compares the digest, and
is atomic: any failure leaves the destination empty.

**Backup verification (§13.5).** `POST /backup/verify`. Copies the live
database with `VACUUM INTO` (safe while writing; a plain copy of a hot
WAL is the classic backup that verifies in the lab and fails in the
fire), verifies the chain, rebuilds every projection from zero, compares
digests, and reads real content back — a database can pass every
integrity check and still be empty.

**Chaos (§34.1).** `test/chaos/kill-points.test.ts`. 200 seeded
iterations, each killing at a randomized instruction boundary by closing
the substrate and reopening the file with entirely new objects. After
each: the chain verifies, projections rebuild byte-identically, every run
is in a terminal or resumable state, and no effect key is committed
twice — checked in the log *and* at the fake remote. The seed is in every
failure message. Runs in 1.8s.

**The endpoints §29 lists.** Vault (`/vault/secrets`, rotate, destroy,
lock, unlock, panic), `/persona`, `/metrics`, `/events`,
`/memory/identity-card`, `/export`, `/import`, `/backup/verify`. A locked
vault is **423**, not 500 — "unlock and retry" is a different instruction
to a client than "something broke". Panic requires the literal string
`"destroy my secrets"` and the refusal says that every existing backup
becomes unreadable too. Test 54 walks §29's own list and fails if any
route is missing.

**Security is finally wired in.** `createSecurity()` existed since M1 and
nothing in `main.ts` constructed it, so the vault, the keyring and the
model-request firewall were real code that no running agent used. They
are now built at the composition root, before anything that could write a
secret into an event, and the invoker resolves `secret://` references
inside the vault boundary. A locked keyring reports **L4** on the
degradation ladder.

**The debts M7 and M8 wrote down.** `effectsCommitted` is now the outbox
read model — the action-claim check can tell "a tool ran" from "the email
was actually sent". `governance.contradicting` is now filled from the
recall's contradiction signal, so `disagreement-surfaced` can return
something other than `unverifiable`.

**A wiring audit.** `test/integration/wiring.test.ts` asserts the one
thing no unit test can: that each layer is *constructed by the
composition root and reachable through the API the UI uses*. It exists
because of the vault — real code, unit-tested, never built by `main.ts`
for eight milestones. It also diffs the client's route list against the
server's route table, which catches the rename that unit tests on both
sides happily survive.

**Veo.** Settings → *How it sounds* (the persona editor, with "what the
model is actually told" expandable), *How it is doing* (the metrics,
each with its budget in words), and *Backup and portability* (verify,
export). Three new e2e tests.

## Found

Four real defects, all found by tests written for this milestone.

**1. Usage counters were not in the log — an invariant-1 violation.**
Recall bumped `facts.use_count` and `last_used_at` with a direct
`UPDATE`. That state existed nowhere in the event log, so a rebuild
reset it: §34.2's "byte-identical" claim was quietly **false on any
database that had actually been used**, and a restore would have silently
degraded decay scoring. Found by pointing `POST /backup/verify` at the
accumulated e2e database rather than a freshly seeded one — which is
exactly the argument for building the verifier. Fixed by making
`memory.used` an event the facts projector applies. Regression test added
to `rebuild-identity`.

**2. `bySubject()` took 530ms at 50k facts.** The hottest query in the
memory layer, run every turn. The subject is stored as canonical JSON (a
weak point carried since M6), so `json_extract(subject,'$.id') = ?` could
not use any index and scanned every row. Fixed twice over: migration 013
adds an expression index on exactly that expression, and the method is
now bounded by a default limit (no interactive path wants 25k facts; the
"forget everything about X" path passes its own). 530ms → 63ms.

**3. The expression index broke the write path.** The first version used
a bare `json_extract`, which raises *"malformed JSON"* at insert time for
the plain-string subjects several tests legitimately write. The
bitemporal suite went red immediately. The shipped index guards with
`json_valid`, and `bySubject` uses the identical expression — change one
and the other silently stops using the index.

**4. Metrics were 1.6s at 150k events.** `read()` materialised every row,
including the `message.*` events that are the bulk of a real log and are
used by no metric at all. Naming the 24 types the report reads cut it to
~200ms, and the list doubles as documentation of the report's input.

## Deferred

- **`revise` is still detected and never executed.** A remedy that
  rewrites the model's words before the user sees them is a harder thing
  to make honest than it looks: it needs its own audit trail, its own
  "this was revised" surface, and a second model call whose output is
  itself ungoverned unless the gate is re-entered. Shipping that in the
  last week of the last milestone is how you get an agent that edits
  itself badly. It is reported in the trace and in
  `/constitution/compliance`, which is the honest version of not having
  it.
- **No merge on import** (decision 038), **no remote backup target**, **no
  Prometheus scrape format** — all reasoned in the design note.
- **One worker.** The lease fencing is built for several; nothing starts
  a second, so multi-worker chaos would test code that does not exist.
- **The 100k pass is `npm run perf`, not part of the suite.** §34.12
  requires the whole suite under 60 seconds offline; seeding 100k events
  takes longer than that alone. The suite keeps the 10k regression
  detector. A team that makes its test suite slow stops running it.

## Unsure

- **Whether `DEFAULT_SUBJECT_LIMIT = 2_000` is the right number.** It is
  far above any real subject and far below the pathological case that
  caused the stall. It is a constant with a comment, not a config key,
  until someone has a reason.
- **Whether the persona belongs in block 1 at all.** The alternative — a
  fifteenth block — is a change to §21 that this milestone had no reason
  to make, but a future model with a much smaller window might want voice
  to be evictable after all. Decision 036 records the reasoning so the
  reversal is cheap.
- **Whether import should ever merge.** Refusing is right today. The
  first person who runs two agents and wants one will disagree, and they
  will be asking for a feature with a genuinely hard core.
- **The chaos suite's kill model.** Closing the substrate reproduces
  "everything not committed is gone", which is what matters, but it does
  not reproduce a torn write at the filesystem level. SQLite's own
  guarantees cover that and are not this repo's to re-test — but it is an
  assumption, and it is written down here rather than left implicit.
