### The call pipeline

```
resolve → capability check → trust floor → validate INPUT → resolve secrets
  → external? write effect.intended → execute (timeout) → validate OUTPUT
  → absorb oversized results → render for the model → zeroize → observe
```

Three properties are worth stating because they each cost something:

**Input *and* output are validated.** Output validation feels redundant until a
tool returns a string where the schema says number, and the model receives it
as fact. `test.liar` exists only to prove this is caught.

**Every failure is an observation.** A tool that throws, hangs, returns garbage,
is not registered, or is refused by policy all produce `{ok: false, text}` and
the run continues. Nothing escapes the invoker. Invariant 11.

**Trust belongs to the channel, not the payload.** A tool can claim its result
is `SYSTEM`; it is recorded at the trust of the channel it came through. The
`tool.succeeded` event carries the result's trust, so the next step's effective
trust is computed over a log that already knows.

### Exactly-once, concretely

Three states exist after a crash, and they are not interchangeable:

| Log says | Means | Action |
|---|---|---|
| nothing | it never started | run it |
| `intended`, no `committed` | **unknown** | ask the remote; if you cannot, ask the person |
| both | it happened | return the recorded result |

`reconcile()` prefers, in order: `queryEffect` → `idempotent` → escalate. It
**never retries** a non-idempotent effect with an unknown outcome. The key is
`hash(tool, version, canonicalInput, stepId)` — canonical so `{a,b}` and
`{b,a}` do not double-pay, step-scoped so two deliberate identical sends in two
steps both happen.

The `effects` table rejects `DELETE`, rejects un-settling a committed row, and
rejects rewriting a key. Evidence that an effect may have happened is not
something a later bug gets to erase.

## Found while building

**A tool could leak a secret into the model prompt.** The event log redacts on
append, so the log was clean — but the observation goes straight from the
invoker to the next prompt and never passes through the log. A hostile tool
could put its resolved secret in its own output and hand it to the model with
nothing in the way. Fixed: all observation text is redacted on the way out, and
`redactor` is a **required** dependency of `Invoker`, not an optional one. An
optional redactor is one careless construction away from a silent leak, and
nothing looks wrong when it happens.

The adversarial test that caught it was initially passing while proving
nothing: `secretsRequired` wants a vault ref, I had given it a bare name, so
the tool never received the secret it was supposed to be stealing. The test now
asserts the theft succeeded *inside* the tool before asserting it failed at the
boundary.

**The model was never told what arguments a tool takes.** `specsFor` returned
`parameters: {type: 'object'}`. Decision 020.

**The `artifacts` table was a placeholder.** Migration v5 adds `step_id`,
`media_type`, `sha256`. Added as a migration, not an edit to `001-init.ts` —
the checksum guard refused, which is the guard working.

**Loop detection must run before the tool-availability check.** I had the order
backwards and a looping model with no invoker reported `tools-unavailable`,
which is true but not the useful truth.

**`clock.now` the tool and `clock.now()` the port method share their text.**
Invariant 9's test originally grepped for substrings and so measured spelling
rather than coupling. It now matches the name as a quoted literal, which is
what "kernel code names a tool" actually looks like.

## Deferred

- **Approvals.** `risk: 'dangerous'` currently refuses and reports its `dryRun`.
  M4 turns that into a real approval round-trip.
- **Compensation is recorded, never triggered automatically.** `compensate()`
  is required of non-idempotent external tools and called only on request.
  Automatic rollback needs the policy engine.
- **`reconcile()` is not called on boot** — nothing calls it yet but tests and
  the demo. It wires into startup in M4 alongside the approval queue.
- **Egress DNS resolution is injectable and unset in production.** `resolveDns`
  defaults to no resolution, so rebinding protection is only active when a
  resolver is supplied. M9.
- **`src/interface/stream.ts` still has no redaction.** Carried from M2 and now
  more visible: the invoker redacts, the SSE stream does not. M4.

## Unsure

- **`effectiveTrust` is recomputed per step by scanning the step's events.**
  Correct and O(events in step). Fine now, suspicious at a million events.
- **Artifact absorption at 4 KiB inline / 800-token render budget** are guesses.
  No evidence yet about what makes a model's behaviour worse.
- **Whether `queryEffect` will be implementable for most real tools.** It is the
  difference between a crash costing a database query and costing a human
  interruption, and it depends entirely on the remote API. If most cannot, the
  escalation path needs to be much better than a log line.
