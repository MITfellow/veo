# M0 — Substrate · complete

**Gates:** `tsc` clean · 81 tests passing in ~14s (budget: 60s) · demo runnable
via `npm run demo` · `npm run verify-chain -- <db>` works against a real file.

The M0 bar from §33 — *append 10k events, drop every projection, rebuild from
the log alone, byte-identical result* — passes. It is
`test/integration/rebuild-identity.test.ts`, it takes 2.8s, and it compares a
~3MB serialisation of every derived table including the FTS index.

## Built

**Ports and fakes** (`ports.ts`, `clock.ts`, `ids.ts`, `log.ts`, `hash.ts`)
Every seam declared in one file, including the ones M2–M6 will need
(`ModelProvider`, `Embedder`, `FileStore`, `Net`) so the layering is visible
before anything depends on it. `FakeClock` moves by ms, days, calendar months
and years, clamping 31 Jan + 1 month to 28 Feb rather than overflowing.
Composing the whole substrate from fakes is one call:
`createTestSubstrate()`.

**ULID + determinism** In-tree, clock- and RNG-injected (D-006). Monotonic
within a millisecond; a backwards clock step cannot produce an id that sorts
before one already issued.

**Canonical JSON + hashing** Keys sorted at every depth, `undefined` and
absent collapse, `null` preserved, bigints and bytes tagged rather than
dropped, `NaN`/`Infinity`/`Date` rejected outright because JSON would corrupt
them silently.

**Event log** Closed union of 51 event types, each with its own zod payload
schema; exhaustiveness is itself a test. `append()` validates, redacts, hashes
and projects inside one transaction. Hash covers every field except the hash —
so reordering, reattributing or editing an event all break the chain.
`verifyChain()` pages through the log and distinguishes a sequence gap from a
broken link from a content edit. `UPDATE` and `DELETE` on `events` are
rejected by database triggers, not by convention.

**Redaction before append** Registered secret values plus eleven patterns,
applied by `append()` itself so no call site can forget. Keys are redacted as
well as values; overlapping secrets resolve longest-first; placeholders name
the label and never a prefix of the value. Fuzzed over 500 payload shapes.

**Upcasters** Read-time, composable across versions, append-only. Verified not
to touch the stored row and — the subtle one — not to break the hash chain:
verification hashes the bytes as stored, never the upcast form.

**Bitemporal fact store** Valid time and transaction time as independent axes.
`CHECK (json_array_length(sources) >= 1)` enforces invariant 5 in the schema,
not just in zod. Crypto-shred leaves the row and destroys the content, so a
deletion is auditable rather than indistinguishable from never-happened.

**Projections** sessions, messages, runs, entities, artifacts, facts (+FTS5).
None reads the clock; all take time from `event.ts`, which is tested by
advancing the clock five years and rebuilding.

**Config** One zod schema, env-driven via `ARISH_SECTION__KEY`, parsed once,
deep-frozen. Nothing reads `process.env` anywhere else.

## Found while building

**A hash-verification bug that would have fired years from now.** `verifyChain`
originally hashed the *upcast* payload. The first time any event type changed
schema, every historical event of that type would have been reported as
tampered — an integrity alarm with no integrity failure, which is worse than
no alarm. Fixed by verifying against the stored bytes
(`verifyRowHash`), with a regression test that simulates a v1→v2 migration and
asserts the chain still verifies.

**Supersession was modelled wrong.** See `docs/decisions/005-*`. Writing
`superseded_at` when the *world* changed retracts a record that is still true,
and "where did she work in March?" returned nothing. The fix separates "the
world moved on" (valid time) from "I was wrong" (transaction time). The test
now asserts three different answers to three similar-sounding questions.

Both were caught by tests written before the code, which is the argument for
§36 in a sentence.

## Deferred (with reasons)

- **`Dialect`** — declared in the design note, not yet extracted. There is
  exactly one engine and no second one to generalise against; guessing at the
  abstraction now would produce the wrong one. It becomes real at M9.
- **Snapshots / log compaction** — `rebuild()` replays from seq 1. At 10k
  events that is 2.8s. It will need periodic snapshots somewhere around 10^6
  events; the shape (snapshot = projection state + seq, replay from there) is
  obvious and the schema already carries `projection_state.last_seq`. Not
  building it before there is a number to tune against.
- **Per-projection incremental catch-up** — `projection_state.last_seq` is
  written but not yet used to resume a single lagging projection. Needed only
  once projections can be rebuilt independently, which is an M9 concern.
- **`CryptoPort` implementation** — the interface is declared; Argon2id, HKDF
  and AEAD land in M1 where they are actually used.
- **Embeddings in `facts_fts`** — lexical half only. The vector half is M6, and
  the hybrid scorer needs both halves at once to be tuned meaningfully.

## Unsure

- **Is `events.payload` the right place for large blobs?** Right now a tool
  result goes in the payload. Past a few hundred KB this will bloat the log and
  slow `verifyChain`. The likely answer is an artifact store with the payload
  holding a reference and a hash. Deferring to M3, when tool results exist and
  there is a real size distribution to look at.
- **`correlationId` defaulting to the event's own id.** It guarantees nothing
  is unattributable, but it means a stray event starts its own correlation
  rather than failing loudly. It may be better to require one explicitly above
  L1. Revisit when the orchestrator exists (M5/M8).
- **Counting 10k events as the rebuild bar.** It passes comfortably, but a
  ten-year log is plausibly 10^6–10^7 events. The test should probably grow a
  nightly variant at 10^6 once snapshots exist. Noting it rather than silently
  treating 10k as "proved at scale".

## Demo

```
npm install
npm run demo                              # the four claims, end to end
npm run verify-chain -- /tmp/arish-demo.db
npm test
```

The demo appends a small history, hands the agent an API key and shows it is
absent from the log, tampers with event 2 on disk and shows the chain naming
the exact row, answers the Maya-employer question on both timelines, then drops
every projection and rebuilds to the same digest.
