## Built

### The key hierarchy (§13.1)

```
passphrase ──Argon2id(16B salt, 64MiB/t3/p1)──► Root Key   (memory only, never stored)
                                                   │
                                     HKDF("arish/v1/mdk-wrap")
                                                   ▼
                                                  KEK ──wraps──► MDK ◄──wraps── Recovery Key
                                                                  │                  ▲
                                            HKDF("arish/v1/index")│                  │
                                                                  ▼        Argon2id(salt2)
                                                            Index Key              │
                                       HKDF("arish/v1/item:" + id)           recovery code
                                                                  ▼          (25 chars, 125 bits)
                                                          per-item key
```

**No table in the database stores a key.** `keyring` stores two *wrapped*
copies of the MDK, two salts, and the Argon2 parameters. Everything else is
derived on demand and zeroized after use.

Two independent wraps of the same MDK is what makes passphrase rotation cheap:
rotation rewrites 32 bytes of wrap and re-encrypts **nothing**. Tested
explicitly — data written before a rotation still decrypts after it.

### Four design choices worth naming

**1. `useSecret(ref, ctx, fn)` is the only door.** There is no `get`, no
`resolve`, no `peek` — not as a convention, as an *absence*. The callback
receives a `Uint8Array` (strings cannot be zeroized, D-012) which is wiped in
a `finally` even when the callback throws. Because every read goes through one
scoped function, "has anything touched my bank key since March?" is answerable
(D-012, `audit.ts`).

**2. The firewall refuses; it does not scrub.** A scrubbed request goes out
successfully and nobody ever learns that something upstream is putting
credentials into prompts. A refused one is a bug report. The error names the
label and the **path** (`messages[1].content`) and never the value.

**3. Trust is computed, not declared.** `effectiveTrust` walks the causation
chain and takes the minimum. A step can *claim* DERIVED; if a `FOREIGN` tool
result is anywhere in its closure the step is FOREIGN, and FOREIGN holds
exactly three capabilities: `fs:write:sandbox`, `memory:write:quarantined`,
`approval:request`. No prompt is consulted. Prompt injection does not fail
because the model resisted it; it fails because the capability is not in the
list.

**4. Capability ceilings are nested, enforced at module load.** A lower trust
level holding a capability a higher one lacks would mean *dropping* trust
grants something — `assertCeilingsAreNested()` throws at import if the table
is ever edited into that state. A test caught this for real: `DERIVED` was
missing `memory:write:quarantined`.

## The M1 bar: zero leaks

`test/adversarial/secret-leakage.test.ts` — 50 secrets of five realistic
shapes (API keys, GitHub tokens, DSNs, PEM blocks, AWS keys) × 200 operations,
each one doing something deliberately careless:

| The mistake | Caught by |
|---|---|
| Interpolated into an event payload | `Redactor`, at append, before hashing |
| Put in a stack trace | same |
| Used as an **object key** | same |
| URL-encoded into a tool argument | same — **after a fix, see below** |
| Written to the operational log | `JsonLogger` → redactor — **after a fix** |
| Built into a model request | firewall, refuses |
| Dumped into a trace | firewall, refuses |

Surfaces scanned for all 50 values in both plain and url-encoded form: every
event payload, **every row of every table in the database**, every log line,
and the export. **Zero hits.** Every leaky model request and trace: caught,
100%.

### Three real bugs the tests found

All three were fixed in the **source**. No test was weakened.

1. **The recovery code would not have worked.** The MDK was wrapped under the
   *dashed display* form while unlock normalized first. A correctly
   transcribed code would have failed — discovered on the one day it matters.
   (D-013; the general rule: normalize on write wherever you normalize on
   read.)
2. **The log was not redacted.** The event log redacted faithfully;
   `logger.error('failed', { authorization: token })` wrote the token straight
   to stderr. §13.2 names a log line as a surface. `JsonLogger` now redacts
   the serialized line and `createSubstrate` wires it to the Redactor.
3. **Redaction was literal-only.** A credential interpolated into a URL
   arrives percent-encoded and sailed past a substring match. The Redactor now
   watches every form a secret wears in transit: url-encoded, base64,
   base64url, JSON-escaped.

Bug 2 and bug 3 existed *only* because the adversarial test was written to be
hostile rather than to pass. That is the argument for writing it that way.

## Deferred

- **Egress firewall (§14)** — domain allowlists, rate limits, the outbound
  HTTP boundary. Belongs with the tool layer; there is no outbound call to
  gate until M3.
- **Approval flows (§13, §19)** — `audit.pendingApprovals()` exists and
  returns `[]`; the request/grant/deny lifecycle is M4.
- **Key rotation for the MDK itself** — passphrase rotation ships; rotating
  the MDK means re-encrypting everything and needs the memory stores to exist
  (M6).
- **Hardware-backed keys / OS keychain** — M9 portability.
- **Multi-device** — explicitly out of scope per the spec.

## Unsure

- **Crypto-shredding is weaker than the spec implies, and I want this on the
  record.** §13.3 says deletion destroys the key. Per-item keys are *derived*
  (§13.1), so they cannot be destroyed — only tombstoned and the ciphertext
  overwritten (D-011). Against someone who has the MDK, a pre-shred copy of
  the ciphertext, and bypasses the application, this does not hold. Against
  every path inside this system it does. Revisit at M6: if memory items want
  genuinely destroyable keys, store wrapped per-item keys instead; the
  `ItemCipher` interface would not change.
- **The firewall's 8-character floor.** Below that, redaction shreds unrelated
  text. A short secret is therefore unprotected. Correct answer is probably to
  refuse to *store* a secret under 8 characters — not implemented because it
  is a policy decision about user data I would rather make deliberately at M4.
- **`effectiveTrust` walks the full causal closure on every call.** Fine at
  current depths, O(closure) forever. If M2's loop makes chains long this
  wants memoizing per step, which is safe because history never mutates
  (invariant 2).
- **Panic wipes the keyring row but not the OS page cache or SSD wear-leveled
  blocks.** Honest ceiling of what software can promise; M9 should say so in
  the docs rather than imply more.
