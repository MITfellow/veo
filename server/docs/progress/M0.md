# M0 — Substrate

Design note and test list, written before the implementation (§61).

## What M0 is for

One claim, and everything else in M0 exists to make it true:

> **The event log is the only source of truth. Every other byte in the
> database is a rebuildable projection.**

That claim is cheap to assert and expensive to keep. It is kept by the
`rebuild-identity` test (§16): build ten thousand events of real state, drop
every projection table, replay the log, and compare the two snapshots byte for
byte. Anything that differs is state that was never in the log — state a crash
or a restore would silently lose. The test is the milestone.

Bitemporality (§17) is in M0 for the reason the spec gives: retrofitting it is
a rewrite. The `facts` table ships with both timelines in M0 even though
nothing writes a fact until M5, because the *shape* is what is expensive to
change later, not the code that fills it.

## Design decisions taken here

**Events are a closed set with a schema per type, enforced at append.**
The spec lists ~60 event types across 20 families. Writing payload schemas for
all of them now would be writing M5's and M8's code during M0. Instead the
*type union* is complete and closed (so no later milestone can invent a type
without editing the union), and the *payload registry* carries schemas only
for the families M0 actually emits. `append()` refuses a type with no
registered schema. The effect is that a later milestone cannot forget to write
a schema — the first append fails loudly. Recorded as decision 003.

**Redaction runs before append, not before storage.** The redactor sees the
payload after schema validation and before hashing, so the hash covers the
redacted bytes. A hash over unredacted content would mean the chain could only
be verified by a process holding the secrets.

**The hash chain covers the whole envelope, not the payload.** `prevHash` plus
canonical JSON of every field except `hash` itself. Canonicalisation is
key-sorted and rejects `undefined`, so two processes agree byte for byte.

**Projections are registered, not discovered.** A projector declares the tables
it owns and a `reset()` that clears exactly those. `rebuild()` resets every
registered projector and replays. Discovery by filesystem scan would make the
rebuild depend on the build output, which is not in the log either.

**ULIDs are monotonic within a millisecond.** Crockford base32, 48-bit time,
80-bit randomness, and a counter that increments the random field when two ids
are requested in the same millisecond. Without the counter, ids sort randomly
inside a tick and `ORDER BY id` stops matching `ORDER BY seq`.

**`seq` is assigned by SQLite, inside the append transaction.** It is the true
total order (§15). The event's own `ts` comes from the Clock and may repeat or,
with a fake clock, move backwards; `seq` may not.

9. Hash chain — `hash` covers every envelope field except itself

12. Redaction — structure is preserved; only values are replaced
13. Config — a valid config parses to typed values
14. Config — an invalid config reports **every** problem at once, not the first
15. Config — unknown keys are rejected rather than ignored

18. Event schema — a known type with an invalid payload is refused

22. Append assigns `seq` monotonically across processes sharing a file

### Structural

## Built

All 38 planned tests exist and pass, plus a few that the implementation
suggested. **84 tests, `npm run check` green, 6.5s against a 60s budget.**

| Area | What shipped |
|---|---|
| Ports (§8, §14) | `Clock`, `Ids`, `CryptoPort`, `Logger`, `Storage`, `Statement`, `FileStore`, `Net`. Fakes for the first four; `createTestSubstrate()` builds the lot in one line. |
| Determinism | Hand-written monotonic ULID, `FakeClock` that advances by calendar months, LCG `FakeCrypto` with real SHA-256. |
| Config (§54) | zod, `.strict()`, **every problem reported at once**, environment read only through an injected object. |
| Storage | SQLite + WAL, four frozen migrations, bitemporal `facts` from migration 3. |
| Event log (§15) | Closed 60-type union, payload registry, validate → redact → hash → append, all inside one transaction with the projectors. Hash chain, `verifyChain()`, upcasters with a refuse-the-future rule. |
| Projections (§16) | sessions, messages, runs, captures, facts, entities. Registered, not discovered. Logical snapshot digest. |
| CLI (§53) | `doctor`, `status`, `verify-chain`, `rebuild`, `help`. `--json` on all of them. |

### The gate, verified by execution (§F.4)

- `10k events → drop all projections → rebuild → byte-identical` ✅
- Rebuild is idempotent; a second pass changes nothing ✅
- The gate has teeth: a deliberately rogue projector **does** break the digest ✅
- `VACUUM` does not move the digest — it is logical, not physical ✅
- Live: 4,000 events on disk → `verify-chain` ok → `rebuild` identical ✅
- Live: tampered `seq 1337` → `CHAIN BROKEN at seq 1337`, exit 1 ✅
- Live: `SIGKILL` mid-write → reopen → 500 events, chain sound, projections identical ✅
- `append` 0.03 ms (budget 2) · 10k-event projection query 1.2 ms (budget 100) ✅

### Things the implementation taught me

- **A live SQLite cursor cannot coexist with projector writes.** `rebuild()`
  originally streamed with `iterate()` and threw "database connection is busy"
  the moment the first projector wrote. It pages by `seq` instead — bounded
  memory, no open cursor.
- **"Byte-identical" had to be defined before it could be tested.** Comparing
  the file fails on freelist and `AUTOINCREMENT` noise; comparing unordered
  `SELECT *` passes until it doesn't. The digest is over logical content in a
  total order.
- **The lint rules fought me on day one**, exactly as §D.3 predicted: four
  complexity and length violations. All four were fixed by restructuring, none
  by relaxing a limit.

## Deferred

- **`arish init` / `start` / `unlock`** — M1 and M2. Absent, not stubbed (§61).
  `help` says so rather than advertising them.
- **Payload schemas for 45 of the 62 event types** — decision 003. The names
  are closed now; the schemas arrive with the milestone that emits them.
- **`FileStore` and `Net` have interfaces but no implementation.** Nothing in
  M0 touches a file or a socket, and an unused adapter is untested code.
- **Projection tables for rules, episodes, commitments, approvals, autonomy,
  queue, schedules, outbox, artifacts** — §16 lists them, but each belongs to a
  later subsystem. Adding empty tables now would mean a rebuild test that
  passes by comparing nothing to nothing.
- **Redaction is value- and field-based only.** No pattern matching for
  secret-shaped strings. That belongs with the vault in M1, which is the thing
  that knows what a secret looks like.

## Unsure

- **The `facts` projector has no way to express "this fact came from a fact
  the user later retracted".** Transitive retraction may matter in M5. Noting
  it now because the schema is the expensive part to change.
- **`exactOptionalPropertyTypes` makes `NewEvent` awkward** — optional fields
  need `| undefined` written explicitly. Correct, but it will add friction
  everywhere; worth revisiting if it starts producing `as` casts.
- **Performance budgets are met by a wide margin on an idle sandbox.** 2,000
  events is not 200,000. The real number arrives in M10 and may change the
  indexing.
