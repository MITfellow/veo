# M2 — Memory

**Gate: 451 tests / 36 files / 16.2 s · `tsc` clean · `eslint .` clean · every
function within complexity 10 · `./docs/progress/M2-demo.sh` green against the
built binary.**

M0 built the bitemporal `facts` table and two demonstration queries. M2 owns
everything above it: the store, the lifecycle, entity identity, shreddable
content, recall, and the CLI that makes all of it inspectable by hand.

The test list (`M2-tests.md`) was written before any implementation. Every box
in it is now either ticked below or named in *Deferred* with a reason.

---

## Built

### The store — `src/capability/memory/store.ts`

`assert · supersede · correct · retract · supersedeBy · pin · unpin · used ·
asOf · history · conflicts`.

The 2-D query is real: `asOf({ validAt, believedAt })` gives four different
answers at the four corners of one pair of events, and a test asserts all
four. Supersede closes valid time; correct closes transaction time; nothing
is ever deleted or overwritten.

Trust is enforced on **mutation**, not only on assert. A FOREIGN extraction
cannot supersede, correct or retract a USER fact, and the refusal names the
meet that would have resulted (decision 011).

Confidence decays by stability — volatile halves in a week, slow in a year,
stable never — and a pinned fact never decays, because a pin is a human
saying it matters.

### Entities — `src/capability/memory/entities.ts`

`create · rename · merge · canonicalOf · candidates · all`.

Renaming keeps the old name as an alias, so a note from 2023 saying "Acme"
still resolves after the company becomes "Acme Global". Merging walks the
canonical chain to its end and inherits every absorbed name. A cycle is
refused rather than followed, and a cycle that somehow reached storage
terminates rather than hanging.

`candidates()` narrows; it does not decide. The decision is `entity.resolve`,
a Cognitive Job, so a model can take it over without touching storage.

### Items and forgetting — `src/capability/memory/items.ts`

`put · get · shred · meta · list`.

Content is sealed under the item's own key (decision 006) and lives in
`item_blobs`, which **no projector writes and `rebuild` does not drop**.
Forgetting destroys the key and leaves the ciphertext — asserted by reading
the bytes back out of SQLite and confirming they are unreadable, not by
checking that a row vanished. The tombstone stays auditable. Shredding twice
is not an error.

### Ingestion — `src/cognition/memory/ingest.ts`

capture → quarantine → `memory.extract` → `entity.resolve` → assert.

In `cognition/` and not `capability/` because it calls jobs, and
`capability` may not import `cognition`. The dependency rule chose the
location.

FOREIGN text goes through `Quarantine.admitAsync` or it does not go in at
all: a missing quarantine is a refusal, never a quiet fallback onto the
privileged path.

### Consolidation — `src/cognition/memory/consolidate.ts`

The job proposes; this applies. A pinned fact is never superseded and a
contradiction is raised rather than resolved — both enforced outside the job
so they hold whichever strategy ran. Idempotent: the second run finds nothing.

### Recall — `src/capability/memory/recall.ts`

Lexical, and it says so. Score = 0.5 × word overlap + 0.3 × decayed
confidence + 0.2 × recency + 0.25 if pinned, and every term is returned
alongside the fact so a surprising ordering can be explained rather than
shrugged at. `fact.used` is appended for what comes back, so "what did it
know when it said that" is a query.

### The surface — `arish memory …`

`add · list · recall · history · forget · entities · conflicts · consolidate`,
each with `--json`. `arish status` now reports live/total facts, entities and
items.

### Schema v7 and two new projections

`entity_aliases` and `items` are projections and are in `PROJECTION_TABLES`;
`item_blobs` deliberately is not. The M0 rebuild-identity workload was
extended to feed both — including the update-only events (`entity.renamed`,
`entity.merged`, `artifact.deleted`, `fact.corrected`, `fact.pinned`,
`fact.unpinned`) — because the gate asserts every table has rows *before*
comparing, precisely so a new empty table cannot pass by comparing emptiness
to emptiness.

Eight new payload schemas: `fact.corrected`, `fact.pinned`, `fact.unpinned`,
`entity.renamed`, `entity.merged`, `artifact.created`, `artifact.deleted`,
plus an optional `reason` on `fact.superseded`. No new event *types* — the
union closed in M0 (decision 003).

## What execution changed

Three bugs that compiled, linted and passed a green suite:

1. **`I work at Acme.` stored `Acme.`** The employer pattern allows a dot so
   that "Acme Inc." survives, and it ate the sentence-final stop. Every test
   asserted the predicate, never the value. Fixed with an abbreviation table.
2. **FOREIGN ingestion was dead code.** Confidence was scaled by 0.5 *before*
   the 0.5 floor check, so every web-page fact was dropped at 0.45. All the
   trust assertions still passed, because they described what a stored
   FOREIGN fact looks like without checking one ever arrived. The floor and
   the scale answer different questions (decision 011 §5).
3. **`arish memory history … | grep -q X` crashed with EPIPE.** `grep -q`
   exits on match and closes the pipe; Node raises that as a fatal unhandled
   error. A tool that cannot be piped into `head` is not a Unix tool.

All three were found by running the demo script. None was visible to review.

## Deferred, with reasons

- **Semantic / vector recall.** Needs an embedding model; §2 says no model.
  Recall is lexical and the CLI says so in its own output.
- **`rule.induce` wiring.** The job exists and is contract-tested; rules are
  M8's subject.
- **Scheduled consolidation.** `consolidate` is idempotent precisely so M7
  can schedule it. M7 owns the scheduler.
- **`arish doctor` reporting memory counts** — struck, and moved to `status`.
  `doctor` answers "is this machine fit to run arish" and must work before a
  database exists; counts are facts about one installation's contents.
- **Shredding an item from the CLI.** `memory forget` retracts a *fact*.
  Shredding needs an unlocked vault, and there is no `arish vault unlock` by
  design (M1): a persistent unlocked session is M7's daemon. `ItemStore.shred`
  is built and tested; it has no CLI door yet.
- **Memory over HTTP.** No auth on the HTTP surface yet; exposing recall
  before auth would be worse than not exposing it.

## Unsure

- **The recall weights are a judgement, not a measurement.** 0.5/0.3/0.2 and
  a 0.25 pin bonus were chosen to make the demo order correctly. They are in
  one table so they can be argued with.
- **`PREFIX_MIN = 4`** joins "live" to "lives_in" without joining "car" to
  "cardiology". It will still mismatch somewhere.
- **The 90-day linear recency window** is arbitrary; it is linear rather than
  exponential only because confidence already decays exponentially and
  compounding the two buried anything a month old.
- **`FOREIGN_CONFIDENCE_SCALE = 0.5`.** Halving is a stance, not a
  calibration.
- **Whether the entity registry should ever auto-create.** It currently never
  does, which means an unresolved mention is stored as a plain string. That is
  recoverable but it is not tidy.
- **`MAX_CHAIN = 32`** for merge chains. Nothing in testing came close.
